# Media Mission — เกมกฎหมายภาพยนตร์สำหรับนิเทศศาสตร์

**ชุดพร้อมนำขึ้น GitHub และเชื่อม Render เพื่อเปิดเล่นผ่านเบราว์เซอร์**

ประกอบด้วยตัวเกม HTML/JavaScript ฉากหลัง Three.js จากโค้ดที่ผู้ใช้ให้ ระบบคะแนน Python/SQLite และหน้าจออาจารย์ ไม่มี React/Node build ที่ต้องติดตั้งเพื่อรันเว็บ

## สิ่งที่ต้องทราบก่อนเริ่ม

GitHub ใช้เก็บโค้ด ส่วน Render รันเว็บและฐานข้อมูล นักศึกษาเปิด URL ของ Render ผ่านเบราว์เซอร์ได้จากอินเทอร์เน็ตหลังติดตั้งสำเร็จ **ไม่ต้องเปิดเครื่องอาจารย์ค้างไว้**

GitHub Pages รองรับเว็บแบบ static และรัน Python/SQLite ชุดนี้ไม่ได้ จึงไม่ต้องเปิด Settings → Pages การเปิดไฟล์ index.html โดยตรงหรืออัปโหลด ZIP ลง Pages จะไม่ทำให้ระบบเกมทำงาน

Blueprint นี้เลือก Render `0.5c-512mb` (0.5 CPU / RAM 512 MB) และ persistent disk 1 GB ซึ่ง **มีค่าใช้จ่าย** ตรวจราคาปัจจุบันในหน้า Render ก่อนยืนยัน อย่าเปลี่ยนเป็น free โดยถอด disk เพราะคะแนนอาจหายเมื่อรีสตาร์ตหรือ deploy ใหม่

ชุดนี้ยังไม่ได้เผยแพร่ให้คุณ และไม่ได้สร้างบัญชีหรือสมัครบริการใด

## 1. นำไฟล์เข้า GitHub

1. แตก ZIP ให้เห็น `render.yaml`, `server.py`, `index.html` และ `README.md` อยู่ด้วยกัน
2. สร้าง repository ใหม่บน GitHub เช่น `media-mission` แนะนำ **Private** เพราะ `content.py` มีเฉลยข้อสอบ
3. เลือก **Add file → Upload files** แล้วอัปโหลดไฟล์และโฟลเดอร์ภายในชุดนี้ ให้ `render.yaml` อยู่ที่ราก repository ไม่ซ้อนอยู่ใต้โฟลเดอร์ `media-mission-github`
4. อย่าอัปโหลดแค่ ZIP เพราะ Render ต้องอ่านไฟล์ที่แตกแล้ว
5. ถ้าใช้ Git บนคอมพิวเตอร์ ให้นำเข้า `.gitignore` และ `.github/workflows/test.yml` ด้วย โฟลเดอร์ที่ขึ้นต้นด้วยจุดอาจซ่อนอยู่ใน File Explorer
6. กด Commit changes

ห้ามอัปโหลด `data/`, ฐานข้อมูลคะแนน, รหัสอาจารย์จริง หรือ `.env` ที่มีความลับ ชุด ZIP นี้ไม่ได้รวมข้อมูลเหล่านั้น

## 2. เชื่อม Render

1. เข้า https://dashboard.render.com และเชื่อมบัญชี GitHub โดยให้สิทธิ์เฉพาะ repository เกมนี้ตามต้องการ
2. เลือก **New → Blueprint** แล้วเลือก repository ที่สร้างไว้
3. ให้ใช้ไฟล์ `render.yaml` ที่ราก repository
4. ตรวจว่ามี web service `media-mission`, persistent disk 1 GB ที่ `/var/data` และตัวแปร `TEACHER_KEY`
5. ตรวจค่าใช้จ่ายก่อนยืนยันสร้างบริการ รอ deploy จนสถานะสำเร็จ
6. Render จะแสดง URL HTTPS ของบริการ ให้นำ URL นั้นแจกนักศึกษา (ไม่ใช่ URL repository บน GitHub)

ตั้งค่า deploy อัตโนมัติไว้เป็นปิด เพื่อไม่ให้การแก้โค้ดระหว่างคาบทำให้เกมรีสตาร์ต เมื่อต้องการอัปเดต ให้ Commit โค้ดแล้วสั่ง Manual Deploy ใน Render หลังจบคาบ

### ถ้าใช้ New → Web Service แทน Blueprint

- Runtime: Python
- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn -c gunicorn.conf.py wsgi:application`
- Health Check Path: `/healthz`
- ใช้บริการที่รองรับ persistent disk และเพิ่ม disk ที่ `/var/data`
- ตั้ง `MEDIA_DATA=/var/data/media-mission`, `MEDIA_PRODUCTION=1`
- ตั้ง `TEACHER_KEY` เป็นค่าสุ่มใหม่อย่างน้อย 24 ตัวอักษร เก็บเป็นความลับใน Render เท่านั้น
- ใช้ instance เดียวและ Gunicorn worker เดียวตามไฟล์ตั้งค่า เพราะใช้ SQLite และ transaction lock ร่วมกัน

## 3. เปิดคาบเรียน

1. ไปที่หน้า Environment ของบริการใน Render แล้วคัดลอกค่า `TEACHER_KEY` ที่ระบบสร้างให้
2. เปิด URL เกมตามด้วย `/admin` และกรอกรหัสนี้ อย่าแจกให้นักศึกษา
3. กดสร้างห้องใหม่ แล้วแจกรหัสห้องพร้อม URL เกม
4. รหัสห้องเดิมบนเครื่องอาจารย์ เช่น `BBDAA8` ไม่ได้ย้ายมาด้วย ต้องสร้างห้องใหม่บนเว็บออนไลน์
5. ให้นักศึกษากรอกรหัสห้อง รหัสนักศึกษา และชื่อเล่น เข้าครบแล้วเลือกเวลา 30/40/45 นาทีและกดเริ่มพร้อมกัน
6. นักศึกษาเปิดเกมผ่านมือถือหรือคอมพิวเตอร์ได้ ไม่ต้องอยู่ Wi-Fi เดียวกันเมื่อใช้โฮสต์ออนไลน์
7. อาจารย์กดอัปเดตสถานะเพื่อตรวจความคืบหน้า ปิดรอบและเปิดเฉลยได้ และดาวน์โหลด CSV เพื่อเก็บเป็นหลักฐานคะแนน

## การเล่นและการคิดคะแนน

- นิยาม 4 ข้อ: แยกภาพยนตร์กับวีดิทัศน์ก่อน ต้องตอบถูกทั้งการจำแนกและเหตุผล
- ฝึก 6 ภารกิจ: สลับบทบาทผู้กำกับ ผู้จัดจำหน่าย และผู้ประกอบกิจการ ผิดแล้วเห็นเหตุผลและลองใหม่ได้
- ประเมิน 5 ข้อ: การตัดสินใจ 1 คะแนน + เหตุผล 1 คะแนน รวม 10 คะแนน บันทึกครั้งแรกที่กดส่ง
- การ์ดกฎหมายเปิดได้ทุกช่วง ไม่มีการหักคะแนนและไม่มีโบนัสความเร็ว
- คะแนนเกม: นิยาม/ฝึกผ่านครั้งแรก 150 XP ลองใหม่จนผ่าน 100 XP ประเมิน 100 XP ต่อส่วนที่ถูก สูงสุด 2,500 XP
- เฉลยและคะแนนประเมินเปิดเมื่อทุกคนส่งครบ หมดเวลา หรืออาจารย์ปิดรอบ ข้อที่ยังไม่ตอบได้ 0 คะแนน
- ตารางอันดับแสดงชื่อเล่น คะแนนเท่ากันเป็นอันดับร่วม ไม่แสดงรหัสนักศึกษา และไม่แสดง XP จากประเมินก่อนเปิดเฉลย
- คะแนนคำนวณที่แม่ข่าย ไคลเอนต์ส่งเฉพาะตัวเลือกคำตอบ

## Microsoft Forms

เชื่อมฟอร์มของอาจารย์ไว้แล้ว หน้าสุดท้ายจะแสดงปุ่ม **ส่งคะแนนให้อาจารย์ผ่าน Microsoft Forms** พร้อมกรอกล่วงหน้า:

| ข้อมูล | รหัสช่อง |
|---|---|
| รหัสนักศึกษา | `rf3e987bb0a78489893ef3ffd18583225` |
| ชื่อเล่น | `rc3482652eb70493cb348b6ae23fa8a4f` |
| คะแนนเต็ม 10 | `r8c0b4335a7724aa2bb8a137f6e12a608` |

นักศึกษาต้องตรวจสอบแล้วกดส่งใน Forms เองอีกครั้ง เกมไม่ทราบผลการส่งของ Forms และคำตอบใน Forms อาจถูกแก้ได้ ให้ใช้ CSV จากแม่ข่ายเป็นคะแนนต้นฉบับ

## ข้อมูลและการสำรอง

- ฐานข้อมูลอยู่ที่ `/var/data/media-mission/scores.sqlite3` บน persistent disk และไม่เสิร์ฟผ่านเว็บ
- ควรดาวน์โหลด CSV หลังทุกคาบ โดยเฉพาะก่อนอัปเดตหรือลบบริการ
- ไม่ควรลบ persistent disk หรือเปลี่ยน MEDIA_DATA ถ้าต้องการเก็บข้อมูลเดิม
- ชื่อเล่นปรากฏต่อเพื่อน รหัสนักศึกษาและคะแนนรายวิชาเห็นเฉพาะเจ้าตัวกับอาจารย์
- ระบบยังใช้รหัสนักศึกษาที่ผู้เล่นพิมพ์เอง ไม่ได้เชื่อมบัญชีมหาวิทยาลัย อาจารย์ควรตรวจเทียบรายชื่อก่อนเก็บคะแนน
- ใช้ repository แบบ Private และเก็บรหัสอาจารย์ไว้ใน Render ไม่ใส่ใน source code
- หากสิทธิ์กลับเข้าเกมหาย อาจารย์ออกรหัสกู้คืนเป็นรายคนได้ เครื่องเดิมจะใช้สิทธิ์เก่าไม่ได้

## ทดสอบก่อนแจกนักศึกษา

หลัง deploy ให้เปิดหน้าอาจารย์และหน้าผู้เล่นด้วยเบราว์เซอร์คนละโปรไฟล์ สร้างห้องทดลองแล้วเล่นจนจบ ตรวจคะแนน CSV และลิงก์ Forms ก่อนใช้เก็บคะแนนจริง

ในชุดมี automated tests สำหรับคะแนนเต็ม/บางส่วน การลองใหม่ การป้องกันส่งซ้ำ การซ่อนเฉลย การหมดเวลา การกู้คืน การจำกัดสิทธิ์อาจารย์ การเข้าถึงไฟล์ส่วนตัว และการกรอก Forms

```sh
python -m unittest discover -s tests -v
node --check app.js
node --check background.js
```

GitHub Actions จะรันการตรวจสอบเมื่อ push หรือเปิด pull request หากอัปโหลด `.github/workflows/test.yml` ไว้

ตัวเกมได้รับการทดสอบ WSGI/API ในเครื่องนี้ แต่ยังไม่ได้ทดสอบ deploy จริงบน Render หรือทดสอบโหลดพร้อมกันทั้งชั้น และยังไม่ได้ทำ browser interaction test

## รันในเครื่องเพื่อแก้ไข

Python 3.10 ขึ้นไป:

```sh
python server.py
```

เปิด `http://127.0.0.1:8765` รหัสอาจารย์แบบ local จะอยู่ที่ `data/teacher-key.txt` ถ้าไม่ได้ตั้ง `TEACHER_KEY` ตัวแอปไม่ได้อ่าน `.env` อัตโนมัติ ให้ตั้งตัวแปรผ่านระบบโฮสต์หรือ shell

สำหรับ production บน Linux ให้ติดตั้ง requirements และใช้ Gunicorn ตามไฟล์ตั้งค่า ไม่ใช้ development HTTP server เปิดสู่อินเทอร์เน็ตโดยตรง

## แหล่งเนื้อหา

อ้างอิงตัวบท พ.ร.บ. ภาพยนตร์และวีดิทัศน์ พ.ศ. 2551 และสไลด์ที่ผู้ใช้แนบ ไม่ใช่การยืนยันกฎหมายฉบับปัจจุบัน การ์ดระบุมาตราและหน้า PDF จุดที่สไลด์ 41 สรุปโรงภาพยนตร์กลางแจ้งคลาดเคลื่อน เกมยึดมาตรา 37: ธุรกิจโรงกลางแจ้งยังต้องมีใบอนุญาต แต่ใบอนุญาตใช้ได้ทั่วประเทศ

ไม่มีไฟล์ PDF ต้นฉบับรวมใน repository ฉากหลังอ้างอิง Three.js ของผู้ใช้และโหลดไลบรารีจาก CDN หากภาพโหลดไม่สำเร็จ เกมและคะแนนยังทำงานต่อได้
